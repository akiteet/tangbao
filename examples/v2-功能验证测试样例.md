# 糖码 v2 功能验证 · 综合测试样例

> 适用：糖码 v1.1.0 + v2 补全（P0+P1 九项）——ContextPack 分层 / 写前 Diff 审批 / 紧急保护 / 摘要落库 / 运行指标 / 命令日志落盘 / 评测 runner 等。
> 用法：在任意测试项目里，把「任务样例」整段复制进糖码输入框发送；对照「预期现象」逐项验证。

---

## 一、任务样例（复制发送）

```text
请完成以下三个步骤的任务，每步完成后再进行下一步：

步骤一：在项目里找到一个公共纯函数（如字符串处理、数组处理类），
给它补一条单元测试，覆盖边界输入（空值 / 超长 / 空数组）。

步骤二：修改该函数的签名——增加一个可选参数 maxLength（带默认值），
确保现有调用方无需改动也能正常运行。

步骤三：运行验证——先调用 detect_verification 查看项目可用的验证命令，
再运行与本次修改相关的验证并确认通过；若测试失败，继续修复直到通过。

要求：
- 修改文件前先展示将修改的内容；
- 不要修改与任务无关的文件；
- 不要声称完成，除非验证确实通过；
- 完成后如实报告：修改了哪些文件、每个文件改了什么、验证结果如何。
```

## 二、预期现象对照表（九项新功能）

| # | 新功能 | 在样例中的表现 | 验证方式 |
|---|--------|----------------|----------|
| 1 | **写前 Diff 审批**（P0-2） | 每步确认模式下，write/edit 文件时审批弹窗直接显示候选 Diff（绿色新增/红色删除），批准后才写入 | 确认弹窗里能看到 Diff 而不是只有文字描述 |
| 2 | **验证风险分级**（补全 5） | 步骤三 detect_verification 返回「验证风险级别：高/中/低 + 建议」；无脚本时提示「不是浏览器/环境限制」 | 看工具结果里的风险级别与建议文案 |
| 3 | **Phase 状态机 + waiting_approval**（P1-8） | 顶栏药丸阶段随任务推进：理解→探索→规划→实施→验证；审批时显示「等待审批」 | 顶栏药丸实时观察阶段变化 |
| 4 | **Completion Gate**（M4 已有） | 测试失败时糖码不会宣称完成，会注入「完成检查未通过」继续修复 | 观察 gate_blocked 事件与继续修复行为 |
| 5 | **运行状态药丸 + 会话角标** | 运行中切到其他会话/模块，顶栏药丸持续显示「⏳ 运行中 · 项目/会话 · 阶段 · 工具 · 步数 · 耗时」；点击跳回 | 切走再切回，药丸实时刷新；运行会话旁有 ⏳ |
| 6 | **运行指标**（P1-6） | 任务完成后点「历史」，run 行显示：审批 N · 压缩 N · 入 Xk / 出 Yk · 约 $Z | 历史面板查看指标明细 |
| 7 | **命令日志落盘**（P1-5） | 若糖码跑长命令（加 `--session` 或用 run_in_background），结束后可查 artifact://logs/<id> 完整日志 | 工具结果里的 artifactRef / job 面板 |
| 8 | **Checkpoint + 继续**（P0-A/P0-B） | 若任务步数/时长耗尽 → 状态「预算耗尽」+ 自动检查点；点「继续任务」从断点续跑不重复 | 观察 budget_exhausted 与接力条 |
| 9 | **紧急保护闭环**（P0-1） | 上下文接近上限时 toast「已按紧急模式压缩」+ 后端自动存紧急检查点 | 长对话/大任务时观察 |

## 三、自动化跑法（评测 Runner）

```bash
cd E:\AAA_study\front_end\exercise\tangbao

# 1) 起糖码后端（新开一个终端）
npm run server

# 2) 跑单个评测任务（simple-001：修改一个文案）
#    EVAL_MODEL 填你要用的模型 id；EVAL_CWD 填测试项目路径
EVAL_MODEL=deepseek-chat EVAL_CWD=D:/path/to/test-project npm run eval:one -- simple-001

# 3) 跑全部可自动任务（simple-*/med-*/complex-*，safe-*/ctx-* 自动跳过）
EVAL_MODEL=deepseek-chat EVAL_CWD=D:/path/to/test-project npm run eval

# 4) 只读汇总历史运行指标（对应用数据库）
npm run bench -- --db <tangbao 应用数据目录>/app.db
```

评测结束输出成功率/平均步骤/平均耗时，结果保存在 `benchmarks/last-eval.json`。

## 五、回归注意

- 审批弹窗出现时**记得点批准**（每步确认模式），否则 90 秒超时按「未执行」处理；
- 测试项目请用**可写、非重要**的目录（糖码会真实修改文件）；
- 若项目没有 test/lint 脚本，步骤三会提示「未识别到验证命令…不是环境限制」——这是预期行为（不是 bug）。
