# 代码审查

1. 用 git_changed_files / git_diff 拿到本次变更的文件与统计，明确审查范围。
2. 对每个变更文件用 read_file 读取关键片段，重点检查：逻辑正确性、边界条件、错误处理。
3. 按风险点逐项核对：
   - 是否破坏既有调用方（find_references 检查符号引用）
   - 是否有硬编码/凭据/危险命令（grep 扫描）
   - 是否有未处理的空值/异常路径
   - 是否与项目既有风格一致
4. 输出结构化结论：问题清单（按 严重/建议 分级，附文件:行号 与修改建议）、无问题项、总体评价。
5. 不改代码，只输出审查结论；如需修复请等用户确认。
