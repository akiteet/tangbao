# Git 提交规范

1. 用 git_status / git_diff 确认改动范围，只提交与任务相关的文件。
2. 提交信息采用 `类型(范围): 简述` 格式（如 fix(agent): 修复账户切换不生效 / feat(skill): 新增技能）。
3. 禁止提交：密钥、临时调试文件、构建产物（dist）、日志；发现已在暂存区则先排除。
4. 若工作区有用户未提交的无关修改，不得一并提交（保持用户修改原样）。
5. 提交前跑一次相关测试确认改动可运行，通过后再提交。
6. 提交失败（如 pre-commit 钩子）时读取报错修复后重试，不要用 --no-verify 绕过。
